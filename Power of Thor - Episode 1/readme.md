## Что реализовано

- Класс Move, который хранит целевую позицию светa и текущее положение Тора, и каждый ход возвращает строку с направлением перемещения (`N`, `NE`, `E`, `SE`, `S`, `SW`, `W`, `NW`).
- Использована перечислимая маска для направлений (`enum class Action`) и словарь для преобразования битовой маски в строковое представление.
- Входные данные читаются один раз (координаты света и старт Тора), затем в игровом цикле для каждого хода вызывается exec и выводится направление движения.

## Какие были идеи

 - Представить направления как битовую маску (`N=0b0001`, `E=0b0010`, `S=0b0100`, `W=0b1000`), чтобы комбинировать их для диагональных направлений (например, `N|E -> "NE"`).
- Инкапсулировать состояние (цель, начальная и текущая позиции) в отдельном классе Move, чтобы логика перемещения была локализована и легко читаема.
- Обновлять координаты по осям независимо: сначала корректировать x (вправо/влево), потом y (вверх/вниз), формируя итоговое направление комбинированием битов.
- Хранить отображение битовой маски в `std::unordered_map<uint8_t, std::string>` для простого преобразования в текстовое представление команды.
## Сложности

- Параметр `remaining_turns` не используется, но для сохранения интерфейса передаётся в `exec`.
