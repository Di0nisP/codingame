## Что реализовано

- Реализован оптимизированный алгоритм на основе динамического программирования с предвычислением прибыли (`earnings`) и следующей позиции (`nextPos`) для каждого старта.
	1.  Дублирование массива `q`, чтобы получить `q2`. Позволяет скользить по окну длиной `N`, не заботясь о циклической природе очереди.
	2. Предвычисление заработка и следующей позиции (O(N)).
	3. Симуляция запусков с обнаружением циклов (O(C)).


```rust
Параметры:
L = 5   (вместимость аттракциона)
C = 5   (число запусков)
Оригинальная очередь q:       [2] [3] [4]
Дублированная очередь q2:     [2] [3] [4] [2] [3] [4]

Предвычисленные значения:
earnings:  [2+3=5] [3] [4]   // сколько людей сядет, если стартуем с позиции i
nextPos:   [2] [2] [0]       // следующее начало очереди после посадки

Начальные значения:
pos = 0, total = 0, ride = 0

--------------------------------
Ride 1:
  pos = 0
  earnings[0] = 5  -> total = 5
  nextPos[0] = 2   -> pos = 2
  ride = 1

Очередь (индексы в q):
[2] [3] [4]
 pos=2 -> указывает на 4

--------------------------------
Ride 2:
  pos = 2
  earnings[2] = 4  -> total = 9
  nextPos[2] = 0   -> pos = 0
  ride = 2

Очередь:
[2] [3] [4]
 pos=0 -> указывает на 2

--------------------------------
Ride 3:
  pos = 0 уже был на ride = 0 -> цикл обнаружен!
  cycleLen = ride - prevRide = 2 - 0 = 2
  cycleProfit = total - prevTotal = 9 - 0 = 9
  remaining = C - ride = 5 - 2 = 3
  cyclesToSkip = remaining / cycleLen = 1
  total += 9 -> total = 18
  ride += 2 -> ride = 4
  pos остаётся = 0 (начало следующего цикла)

--------------------------------
Ride 5 (остался последний запуск):
  earnings[0] = 5 -> total = 23
  nextPos[0] = 2 -> pos = 2
  ride = 5

--------------------------------
Итог:
total = 23
```
## Какие были идеи

- Первая идея: моделировать каждый запуск, переставляя элементы в векторе (сдвиг очереди после каждой поездки). Этот подход оказался неоптимальным из-за высокой сложности (много вставок/удалений в векторе).
- Оптимизация: перейти к предвычислению на массиве с дублированием (`q2`), что позволило эффективно определять, сколько групп помещается за один запуск. Для ускорения добавлен механизм поиска циклов: запоминание состояний по индексу и накопленной прибыли.

## Сложности

- Правильная обработка циклов: важно корректно вычислить длину цикла и прирост прибыли, чтобы избежать зацикливания.
- Баланс между памятью и скоростью: хранение дополнительных массивов `earnings`, `nextPos`, `seenRide`, `seenTotal`.
- Обеспечение точности при больших числах (`long long` для сумм).
